# tdl Web GUI

基于**预编译 tdl.exe**（不改 tdl 源码）的本地 Web 可视化控制台：浏览器里登录、下载、转发、上传、导出消息、浏览下载目录，实时查看逐文件进度。

```
tdl_source\          tdl 源码（仅参考，GUI 不修改它）
tdl_Windows_64bit\   预编译 tdl.exe（GUI 调用它）
gui\                 ← 本项目（Node.js）
```

## 快速开始

1. 安装 [Node.js](https://nodejs.org/) 18+（本机已装 v24）
2. 双击 `start.bat`（首次运行自动 `npm install`）
3. 浏览器打开 <http://127.0.0.1:8560>

> 没装过 tdl 的机器无需任何 tdl 配置——GUI 会自动找到旁边的 `tdl_Windows_64bit\tdl.exe`；找不到时用环境变量 `TDL_GUI_TDL_PATH` 指定。

## 全局快捷指令 tdlw（推荐）

装一次之后，**任意目录**敲 `tdlw`（别名 `tblw`，两个名字等效）即可启动——**不弹出任何命令行窗口**，服务在后台静默运行，并自动打开浏览器。

```bat
cd gui\bin
install-tdlw.bat          :: 安装（一次性，会检查依赖并配置 PATH）
```

之后：

| 命令 | 作用 |
|---|---|
| `tdlw` | 静默启动服务并打开浏览器；**已在运行则只打开浏览器，绝不重复启动，无任何弹窗** |
| `tblw` | `tdlw` 的别名，两个名字等效 |
| `tdlw-stop` | 停止服务，释放 tdl 数据库锁，并清理启动锁 |
| `uninstall-tdlw.bat` | 卸载快捷指令（GUI 本体与下载文件不受影响） |

**防重复启动（三重防护）**：

1. **运行中检测**——启动前先探测服务状态；已在运行就只打开浏览器，不再起进程，也不弹任何提示。
2. **启动锁**——用原子创建（`CreateTextFile` 带 overwrite=False）的锁文件当互斥量。即使**同时连点多次**，也只有一个实例能真正启动，其余会等待并复用。
3. **陈旧锁自愈**——若上次是崩溃退出留下的锁（超过 90 秒且服务无响应），会自动清除并正常启动，不会永久卡住；若锁很新，则提示「另一个实例正在启动，请稍候」，而不是抢着再起一个。

说明：
- 通过 `wscript` 运行 `.vbs` 实现无窗口启动；服务日志写入 `gui\data\server.log`（启动失败时会弹窗提示并给出日志路径）。
- 启动锁只在启动窗口期存在，服务起来后自动释放（`gui\data\tdlw.lock` 通常看不到属正常）。
- 端口被占用时会明确提示「端口已被其他程序占用」，而不是静默失败。
- 若提示 `tdlw 不是内部或外部命令`，重新打开一个终端窗口（PATH 需要新会话生效）。
- 想改地址/端口：设置环境变量 `TDL_GUI_PORT` / `TDL_GUI_HOST`。

## 功能

| 页面 | 说明 |
|---|---|
| 仪表盘 | 账号状态、tdl 版本、队列状态、最近任务 |
| 下载 | **每条链接生成一个独立任务卡片**；支持暂停 / 继续，逐文件显示**落盘绝对路径**，实时进度条 |
| 转发 | clone/direct 模式、目标路由、改写文本、演练模式 |
| 上传 | 本地文件/目录上传，话题、caption 表达式、--rm |
| 导出消息 | 按最近 N 条 / ID / 时间区间导出 JSON，供下载使用 |
| 文件 | 下载目录浏览器，图片/视频/音频在线预览，直接下载 |
| 账号登录 | **一键从桌面客户端导入**（自动列出账号昵称）、网页扫码 / 手机号+验证码 / 2FA，全部在网页完成 |
| 设置 | 连接（代理/命名空间）+ **下载默认设置**（目录/模板/扩展名过滤/并发等） |

## 任务与链接的对应关系

在下载页粘贴**多条链接**时，**每条链接会生成一张独立的任务卡片**（导出 JSON 文件同理，一个文件一张卡片）：

- 提交 3 条链接 → 生成 3 张卡片，各自只包含自己链接的文件，不再嵌套在同一个卡片里
- 每张卡片可**单独**暂停 / 继续 / 取消 / 删除
- 点击创建后，链接输入框会清空（防止误触重复创建）

**执行顺序**：tdl 使用 bolt 数据库，同一时间**只允许一个写入进程**，因此多个任务会**自动排队依次执行**（状态显示「排队中」→「运行中」）。这是 tdl 的硬性约束，多个任务无法真正并行启动。

## 下载任务的暂停与继续（真字节级续传）

下载任务支持**暂停**和**继续**，断点续传是**按字节**的，不会重下已完成的部分。

**为什么需要特殊实现**：tdl 自带的下载器打开文件用 `os.Create()`（O_TRUNC，会清空），且没有任何 offset 处理——暂停后继续会把当前文件**从 0 重下**。这是 tdl 的固有缺陷，不是配置问题。

**GUI 的解法**：tdl 的 `--serve` 模式（HTTP 服务）**完整支持 Range 请求**（返回 `206 Partial Content` + `Content-Range`）。所以下载任务改走 HTTP 通道：

1. 启动 `tdl dl --serve`，从索引页拿到每个文件的路径和大小
2. 文件按 8MB 分块，用**并发的 Range 请求**下载，每块写入 `.part` 文件的对应偏移
3. **暂停** = 中止传输；**已完成的块和每个块内已写入的字节数**都记在 `.part.json` 里
4. **继续** = 只补下缺失的块，块内已下载的部分从该偏移接着传

实测验证：暂停时保留了 30 个部分完成的块共 34.5MB，继续后从 34.5MB 接续到 407MB——**没有任何进度被丢弃**。

> 其他任务类型（转发/上传/导出）仍直接调用 tdl；只有下载走 HTTP 通道。
> `.part` 与 `.part.json` 在下载完成后自动清理。

## 断线自愈（代理/线路闪断不用管）

Telegram 走代理，代理节点到 Telegram 的线路可能**中途劣化或闪断**（表现为速度掉到接近 0、然后全部连接一起报错）。下载引擎对此做了两层自愈：

1. **块级重试**：任何一块 Range 请求失败（连接被重置、提前断开、5xx 等）都会自动重试（最多 4 次，带抖动退避），从块内已下载的偏移接着传，**不会重下整个块**；任务日志里的错误会带上底层错误码（如 `ECONNRESET`）和 tdl 返回的原始错误文本。
2. **serve 进程自动重启**：线路故障有时会把 `tdl --serve` 进程整个带崩（日志会出现 `tdl --serve 进程中途退出（退出码 X）`）。GUI 会自动重启 serve 并从断点续传（最多 5 次）；tdl 临终的错误输出会被完整捕获进任务日志。

只有线路连续不可用、把重试额度耗尽时任务才会失败——此时**进度仍然保留**，修复代理后点「继续」即可接着下。

## 下载速度

速度**主要由并发连接数决定**（在同一代理链路上实测一个 1.7GB 文件）：

| 并发连接 | 实测速度 |
|---|---|
| 1 | ~0.1 MB/s |
| 8 | ~1.2 MB/s |
| 16 | ~2.8 MB/s |
| 32 | ~3.4 MB/s |
| 48 | ~5.4 MB/s |

在「设置 → 性能默认值」里调整，**默认每文件 48 连接**（上限 64），另有一个「同时下载的文件数」（默认 3）：

| 设置项 | 作用 |
|---|---|
| 下载并发连接数（每文件） | 决定**单个文件**的下载速度 |
| 同时下载的文件数 | 决定**多个文件**是否一起下；多链接时不会都排在第一个大文件后面 |

总连接数会分摊到并行下载的文件上（例如 48 连接 ÷ 3 文件 = 每文件 16 连接），所以两者需要配合调整。

> 若速度仍然不理想，瓶颈通常在代理链路本身（可用 `curl --proxy socks5h://127.0.0.1:7890` 测一下代理的实际吞吐）。Telegram 走 MTProto 协议，其吞吐与普通 HTTP 代理转发并不相同。

## 文件落盘路径

任务列表里每个文件都会显示**绝对路径 + 文件名**（例如 `X:\tdl-web\gui\downloads\...\xxx.MP4`），下载完不用去猜文件在哪。任务卡片标题下也会显示该任务的下载目录。

## 配置的职责划分

下载页只保留**本次任务特有**的输入（消息链接、导出 JSON、下载目录）。所有**可复用**的选项统一放在设置页的「下载默认设置」：

| 设置项 | 对应参数 |
|---|---|
| 文件名模板 | `--template` |
| 下载目录（默认值） | `--dir` |
| **下载并发连接数** | 每文件的并行 Range 连接数（决定单文件速度） |
| **同时下载的文件数** | 并行下载的文件数（多链接时同时进行） |
| 仅包含 / 排除扩展名 | `--include` / `--exclude` |
| 自动识别相册 | `--group` |
| 跳过同名同大小 | `--skip-same` |
| 按文件头修正扩展名 | `--rewrite-ext` |
| Takeout 会话 | `--takeout` |
| 从新到旧下载 | `--desc` |

新建下载任务时自动套用这些默认值（任务本身仍可覆盖）。

## 登录方式

推荐**从桌面客户端导入**（免扫码，秒完成）：前提是你本机已登录 Telegram Desktop（官方版或 64Gram/AyuGram 等 fork 均可）。

1. 登录页展开「⚡ 从本机 Telegram 桌面客户端导入」
2. 点「① 读取账号列表」——自动探测最近使用的客户端目录，并**联网查询每个账号的昵称/用户名**（如 `Alice (@alice)`），不再只显示数字 ID
3. 点选要用的账号 → 「② 导入选中账号」

说明：
- 昵称查询走 Telegram 只读接口，需要代理（用设置页里配置的代理）；若某账号会话已失效会标注「信息获取失败」，但 ID 仍可用于导入。
- 导入**不会**登出你的桌面客户端（会自动选择「否」），两者可同时使用。
- 其他方式：扫码登录（二维码直接渲染在网页）、手机号+验证码、2FA 密码输入，均在网页完成。

⚠ 登录会**覆盖**所选命名空间的既有会话（tdl login 的固有行为）。多账号请用不同 `--ns`。

## 使用前提

- **代理**：直连 Telegram 通常不通。在「设置」页填入代理（如 `socks5://127.0.0.1:7890`），保存后对后续任务生效。
- **登录**：进「账号登录」页扫码。⚠ 登录会**覆盖**所选命名空间的既有会话（tdl login 的固有行为），多账号请用不同 `--ns`。
- 会话数据与 CLI 完全共享（`~/.tdl`），CLI 登录过的账号 GUI 直接可用，反之亦然。

## 架构与已知约束

```
gui/
  server.js          HTTP 服务 + JSON API + SSE 实时推送
  start.bat          前台启动（带控制台窗口，便于看输出）
  bin/               tdlw 全局快捷指令的安装脚本与 VBS 启动器
  lib/db.js          SQLite 持久化（node:sqlite 内置，无原生依赖）
  lib/tdl.js         tdl 执行器：ConPTY 统一启动、全局串行队列、进度行解析
  lib/serve-dl.js    基于 tdl --serve + HTTP Range 的真字节级续传下载
  lib/tasks.js       任务引擎（下载/转发/上传/导出），进度快照、暂停/继续、历史
  lib/login.js       登录会话（QR 块字符捕获、验证码/2FA 输入注入、桌面端导入）
  lib/desktop.js     桌面客户端探测 + 账号昵称解析（调用 tools/tdlinfo）
  lib/files.js       下载目录浏览器（路径钳制）
  tools/tdlinfo/     读取 tdata 账号并联网查询昵称的小工具（Go，已预编译）
  tools/tdlsession/  读取当前 tdl 会话对应的账号（Go，已预编译，只读）
  public/            前端 SPA（原生 JS，无构建步骤）
```

## 数据持久化（SQLite）

使用 Node 内置的 `node:sqlite`，数据库文件 `gui/data/tdl-gui.db`（WAL 模式），三张表：

| 表 | 内容 |
|---|---|
| `form_state` | 各表单的**草稿**——任务表单 + 登录页（客户端目录/命名空间/手机号），输入即自动保存（防抖 400ms），刷新页面/重启服务后原样恢复 |
| `recent_values` | 历史值（如用过的下载目录），驱动「下载目录」的**可输入下拉框**，按最近使用排序 |
| `tasks` | 任务历史记录（最近 200 条），启动时自动从旧的 `tasks-history.json` 迁移 |
| `app_state` | 设置项（`settings`）与登录记录（`last_login`） |
| `task_source` | 每个任务的**原始请求**（链接 / 导出文件 / 目录），支持随时「继续」或重跑 |

### 设置持久化

「设置」页的每一项（代理、命名空间、下载目录、并发、模板等）都落 `app_state` 表，同时保留一份 `gui-config.json`（便于手工查看/编辑）。刷新或重启后原样生效。

### 登录状态自动恢复（无需重复登录）

tdl 的会话保存在 `~/.tdl`，**本身就跨重启有效**；GUI 之前只是没记住状态，重启后显示"未登录"造成误解。现在的行为：

1. **启动时自动检测**——服务起来后后台调用一次 `tdl chat ls` 验证会话是否可用（不依赖任何已保存记录，所以 CLI 登录、桌面端导入、GUI 登录产生的会话都能识别）。
2. **记住账号**——检测成功后调 `tools/tdlsession` 读出账号名（如 `Alice`）并存入 `last_login`。
3. **界面如实展示**——顶部标签显示「已登录：Alice（default）」；登录页显示「已登录（重启后自动恢复）」。
4. **会话真失效时**——状态标为「登录已失效」并给出原因，提供「重新检测」按钮，而不是笼统显示未登录。

因此：**登录一次后，重启 GUI 或重启电脑都不需要再登录。** 只有换账号或会话被 Telegram 吊销时才需要重新登录。

表单行为说明：
- **持久化范围**：下载/转发/上传/导出四个页面的所有设置项（含勾选项、高级选项）都会保留，不只是下载页。
- **提交后清空**：只清空「要处理的内容」——消息链接 / 来源 / 上传路径；目录、模板、并发等设置保留，方便连续建任务。
- **下载目录**：既是输入框也是下拉框（HTML `datalist`），可直接输入新路径，也可点下拉选用过的目录。

## 任务状态说明

| 状态 | 含义 |
|---|---|
| 排队中 / 运行中 | 等待或正在执行 |
| **已暂停** | 已优雅中断，进度已保存，可点「继续」 |
| **已完成** | tdl 退出码 0，且**确实处理了文件** |
| **无匹配文件** | tdl 退出码 0，但一个文件都没处理——链接无媒体，或过滤条件把文件全排除了 |
| 失败 | tdl 非 0 退出，或运行中报错 |
| 已取消 / 上次中断 | 手动取消；服务重启时仍在运行的任务 |

### 关于扩展名过滤（重要）

tdl 的 `--include` / `--exclude` 是按**原始大小写**精确匹配文件扩展名的：文件叫 `IMG_7710.MP4` 时，`--include mp4` **匹配不上**，会导致所有文件被静默跳过，而 tdl 仍返回退出码 0。

GUI 已自动处理：你填 `mp4,mkv`，实际会传 `mp4,MP4,mkv,MKV`，因此大小写都能匹配，无需手动区分。

`tools/fix-nomatch.js` 是一次性修复脚本，用于把历史上被误标为「已完成」的零文件任务重新标记为「无匹配文件」（幂等，可重复运行）。

- **串行队列**：tdl 的 bolt 存储是单写者，GUI 把所有 tdl 调用（任务/登录/会话列表）排成一个队列，同一时间只运行一个 tdl 进程。单个任务内部并发由 `-t/-l` 控制。
- **进度解析**：tdl 的 go-pretty 进度表每 100ms 重绘，GUI 从 ANSI 流中解析出每条消息的字节/百分比/速度/ETA；完成/失败标记与日志同样被捕获。
- **交互登录**：tdl 的 survey 提示在管道下无法工作，因此所有 tdl 调用统一跑在 ConPTY 虚拟终端里（node-pty），登录提示（验证码/2FA）由网页提交。
- **历史任务**保存在 `gui/data/tasks-history.json`（最近 200 条）；GUI 重启后仍可见，运行中的任务标记为“上次中断”（下载续传由 tdl 自身的 resume 机制支持，勾选“续传”即可）。
- 端口/地址：环境变量 `TDL_GUI_PORT`（默认 8560）、`TDL_GUI_HOST`（默认 127.0.0.1，仅本机访问）。

## 排错

| 现象 | 处理 |
|---|---|
| 任务失败：`not authorized` | 未登录或命名空间选错，去「账号登录」重新登录 |
| `Current database is used by another process` | 有别的 tdl 进程在占用（含 CLI），关掉它；GUI 重启后再试 |
| 会话列表/任务一直排队 | 串行队列被长任务占用属正常；等它结束 |
| 扫码后提示密码 | 账号开了两步验证，在登录页输入 2FA 密码即可 |
| 连接超时 | 检查「设置」里的代理是否可用 |

## 安全提示

GUI 默认只监听 127.0.0.1，无鉴权。如需局域网访问，请自行加反代+鉴权（API 无身份校验，勿直接暴露公网）。
